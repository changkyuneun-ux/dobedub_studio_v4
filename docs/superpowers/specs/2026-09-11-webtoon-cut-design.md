# 웹툰 이미지 컷 분할 요구사항 및 설계

- 작성일: 2026-09-11
- 대상 제품: DOBEDUB STUDIO v4
- 대상 브랜치: `feat/webtoon-cut`
- 제공 경로: 로컬 개발판과 AWS ECS 배포판
- 실제 처리 위치: 사용자 브라우저의 로컬 실행 영역
- 실험 코드 참조: `/Users/changkyuneun/webtoon Pannel`

## 1. 목적

DOBEDUB STUDIO의 일반 사용자 메뉴에 **이미지 컷 분할** 기능을 추가한다. 생성된 컷의 주 용도는 인쇄가 아니라 향후 I2V 파이프라인의 입력 이미지다. 사용자는 ECS에서 제공되는 DOBEDUB STUDIO에 로그인해 화면과 정책 코드를 받지만, 실제 컷 분할은 사용자의 브라우저 안에서 실행한다. 사용자는 자기 컴퓨터의 파일·폴더·ZIP을 선택하거나 끌어놓고, 브라우저는 그 입력에서 작업 위치와 출력 위치를 파생한다. 결과 컷과 검수 자료는 사용자가 허용한 같은 로컬 위치 아래에 직접 생성한다.

이 기능은 입력 파일을 DOBEDUB 서버, ECS, EFS, S3 또는 RDS에 업로드하지 않는다. 결과 파일도 서버에서 내려받지 않는다. ECS는 로그인, 메뉴, 화면, 버전이 고정된 실행 코드와 정책만 제공한다. 파일 읽기·분석·쓰기는 브라우저의 로컬 실행 영역에서 끝난다.

## 2. 확정 요구사항

1. DOBEDUB STUDIO의 관리자 화면이 아닌 일반 사용자 메뉴에 추가한다.
2. 로컬 개발판과 ECS 배포판은 같은 화면·같은 분리 엔진·같은 출력 규칙을 제공하지만, 어느 경우에도 서버가 사용자의 원본·결과 파일을 처리하지 않는다.
3. 입력과 출력은 모두 사용자의 로컬 파일 시스템에만 존재한다.
4. 파일 본문, 미리보기, 로컬 절대 경로, 파일명 목록을 서버 API로 전송하지 않는다.
5. 사용자는 먼저 처리할 파일·폴더·ZIP을 선택하거나 끌어놓는다. 별도의 작업 위치 선택 컨트롤은 제공하지 않는다.
6. 출력은 입력에서 파생한 작업 위치 안에 `<입력 이름>_cuts` 디렉토리를 생성해 저장한다.
7. ZIP 입력은 `<압축파일명>_cuts/<ZIP 내부 상대경로>/<원본 파일명>/` 구조를 사용한다.
8. 출력 컷은 원본 픽셀 크기를 유지한다. PDF만 300dpi로 페이지를 렌더링한 뒤 분할한다.
9. 컷이 검출되지 않는 표지·목차·판권·인포그래픽 등의 페이지는 페이지 전체를 1컷으로 저장하고 검수 플래그를 남긴다.
10. 컷 경계와 판정 결과를 사람이 확인할 수 있도록 `summary.csv`, `manifest.json`, `_debug/` 자료를 생성한다.
11. 중단 후 재개할 수 있어야 하며 이미 완료한 입력은 조건이 같으면 다시 처리하지 않는다.
12. 컷과 `_debug/` 미리보기를 포함한 모든 생성 이미지는 입력 형식과 무관하게 PNG로 저장한다.
13. 사용자가 실행 중 다른 DOBEDUB 화면으로 이동해도 입력/출력 handle과 작업 상태를 유지하고, 컷 분할 화면에 재진입하면 같은 작업의 상태와 진행률을 복원한다.
14. 처리 시작 전에 모든 원본 이미지와 PDF 페이지를 작업 단위로 확정하고, 종료 전에 각 단위가 최소 1개의 검증된 컷 또는 명시적 오류와 대응되는지 대조해 누락을 숨긴 채 완료하지 않는다.
15. 컷 검출이 0개여서 전체 영역으로 대체했거나 연속 장면을 확실히 나누지 못한 이미지·PDF 페이지는 별도의 검수 필요 목록에 표시해 분할 품질상 누락 가능성을 숨기지 않는다.

## 3. 아키텍처 결정

### 3.1 채택 구조: ECS 제공 + 브라우저 로컬 실행

```text
로컬 FastAPI 또는 ECS/ALB
        │
        │ 로그인 · HTML · JS · 분리 정책 코드만 제공
        ▼
DOBEDUB 브라우저 화면
        │
        ├─ File System Access API: 사용자가 선택한 입력과 파생된 작업·출력 위치
        ├─ Web Worker: 전체 작업 단위 inventory·픽셀 분석·분할·ZIP 해제·PDF 페이지 처리
        └─ 로컬 출력: *_cuts/ 컷·CSV·manifest·debug
```

- 로컬 개발판: 기존 FastAPI가 프론트엔드 번들을 `localhost`에서 제공한다.
- ECS 배포판: ECS가 로그인된 사용자에게 같은 프론트엔드 번들과 정책 코드를 제공한다.
- 두 환경 모두 실제 처리는 브라우저의 Web Worker에서 수행한다.
- ECS task는 사용자 컴퓨터의 파일 경로나 파일 바이트에 접근하지 않는다.
- 서버 DB에는 컷 분할 작업 이력이나 파일 메타데이터를 기록하지 않는다. 재개 정보는 출력 디렉토리의 `manifest.json`이 정본이다.
- 사용자가 고르는 `실행환경` 옵션은 제공하지 않는다. 화면에는 서버 처리 선택지가 아니라 `브라우저 로컬 처리` 상태와 ECS 정책 버전만 표시한다.

### 3.2 이 구조가 필요한 이유

ECS 컨테이너는 사용자의 Mac 또는 Windows 로컬 디렉토리를 직접 읽을 수 없다. ECS에서 Python/OpenCV를 실행하려면 입력 업로드와 결과 다운로드가 필요하므로 확정 요구사항과 충돌한다. 브라우저 로컬 실행 구조는 ECS가 코드와 정책만 제공하면서도 입출력을 사용자 장치에 유지할 수 있는 공통 구조다.

### 3.3 브라우저 지원 범위

- 1차 지원: 데스크톱 Chrome·Edge 최신 버전
- 로컬판의 `http://127.0.0.1`과 ECS판의 HTTPS 모두 secure context 조건을 만족해야 한다.
- `showDirectoryPicker()`와 디렉토리 쓰기를 지원하지 않는 브라우저에서는 실행 버튼을 비활성화하고 지원 브라우저 안내를 표시한다.
- Safari·Firefox·모바일 브라우저는 초기 범위에서 제외한다.

## 4. 사용자 메뉴와 화면

### 4.1 메뉴·라우트

- 영역: 일반 사용자용 독립 최상위 `LOCAL`
- 메뉴명: `이미지 컷 분할`
- 메뉴 key: `webtoonCuts`
- 라우트: `webtoonCuts`
- URL: `/studio/webtoon-cuts`
- 노출 권한: 기존 `jobs:run` 권한 재사용
- 메뉴 위치: `GENERATE` 섹션 위. `GENERATE`와 동등한 최상위 로컬 처리 메뉴로 배치한다.

서버 생성 작업(`Batch 처리`, `Grok 프롬프트 생성`, `Runpod ComfyUI 요청`)과 달리 서버 작업 큐·ECS 산출물 저장 구조를 사용하지 않으므로 `GENERATE` 하위에 두지 않는다. 서버에 파일 처리 API를 추가하지 않으므로 권한은 메뉴·라우트 접근 제어에 사용한다. 클라이언트 번들을 받은 뒤의 로컬 파일 작업은 운영체제와 브라우저가 부여한 디렉토리 권한으로 제한한다.

### 4.2 기본 화면 구성

1. **입력 선택**
   - `파일 또는 폴더 선택` 버튼과 끌어놓기 영역을 제공한다.
   - 사용자가 선택하거나 끌어놓은 파일·디렉토리·ZIP이 입력 원본이 된다.
   - 별도의 `작업 위치 선택` 컨트롤은 제공하지 않는다.
   - 폴더를 선택하면 해당 폴더를 작업 위치로 간주한다.
   - 파일 또는 ZIP을 선택하면 해당 입력의 부모 위치를 작업 위치로 간주하되, 브라우저가 부모 위치 쓰기 권한을 제공하지 못하면 출력 위치 선택을 추가 요청한다.
   - 파일 1개, 여러 파일, 디렉토리 1개 또는 ZIP 1개를 한 작업 요청으로 받을 수 있다.
   - `*_cuts`, 숨김 파일, macOS 메타데이터는 목록에서 제외
2. **처리정보 확인**
   - 입력 선택 직후 브라우저가 사전 inventory를 만들고 처리정보를 표시한다.
   - 표시 항목: 파일 수, PDF 페이지 수, 예상 작업 단위 수, 지원/제외 파일 내역, 작업 위치, 출력 위치, 출력 구조, 기존 결과 발견 여부, 적용 정책 버전.
   - 작업 위치와 출력 위치는 사용자가 직접 고르는 주 입력값이 아니라 입력 선택에서 파생된 읽기 전용 정보로 표시한다.
   - 사전 inventory를 확정할 수 없거나 지원하지 않는 입력이 있으면 쓰기 전에 오류 또는 제외 사유를 표시한다.
   - 사용자는 처리정보를 확인한 뒤 `작업 요청`을 누른다.
3. **자동 감지 정책**
   - 일반 사용자 화면에는 `분리 방식` 선택을 노출하지 않는다.
   - 기본 정책은 `입력 유형 자동 감지`다.
   - PDF는 페이지형/격자형 정책으로 시작하고, 세로로 긴 래스터 이미지는 세로 웹툰 정책으로 시작한다.
   - 자동 판정 결과와 사용된 정책은 완료 후 `summary.csv`, `manifest.json`, `_debug/` 검수 화면에 표시한다.
   - 개발·검증용 강제 모드는 운영 UI가 아니라 내부 테스트 옵션으로만 둔다.
4. **고정 처리 정책**
   - 출력 규칙은 ECS에서 제공되는 고정 정책으로 처리하며 일반 사용자 화면에 선택 컨트롤을 노출하지 않는다.
   - PDF 렌더 DPI: `300` 고정
   - 컷 여백: 세로 웹툰 상하 15px, 페이지형/격자형은 검출 테두리 기준
   - 원본 크기 유지 표시
   - 생성 이미지 형식: `PNG` 고정
   - 기존 출력 발견 시 `재개`, `새 출력 폴더`, `취소` 중 선택
5. **실행과 진행 상태**
   - 입력 개수, 현재 파일/페이지, 생성 컷 수, 경과 시간 표시
   - `시작`, `중지`, `재개` 제공
   - 현재 파일이 끝나는 지점에 중지하며 불완전한 파일은 `.partial` 상태로 남기지 않는다.
6. **완료 요약**
   - 전체·완료·검수 필요·오류·누락 작업 단위와 생성 컷 수
   - `review_required`, `fullpage`, `review_continuous`, `thin`, `many`, `missing_output`, `error` 건수
   - `검수 필요`를 선택하면 해당 원본 파일 또는 PDF 페이지와 `_debug/` 오버레이를 바로 확인할 수 있는 목록 표시
   - 검수 필요 목록에서는 파일 또는 PDF 페이지를 선택하고 재처리 유형을 고른다.
   - `review_continuous` 항목은 재처리 유형 `수평 장면 전환`을 선택한 뒤 `선택 유형으로 재처리`로 다시 분할할 수 있다.
   - 오류·누락 단위만 다시 처리하는 `실패/누락 재시도` 제공
   - `결과 위치 확인` 버튼: 지원 시 출력 handle을 시작 위치로 디렉토리 선택기를 열고, 미지원 시 작업 위치 기준 상대경로 표시

## 5. 지원 입력

### 5.1 지원 입력

- 래스터 이미지: `.jpg`, `.jpeg`, `.png`, `.webp`
- 문서: `.pdf`
- 압축: `.zip`
- 디렉토리: 위 확장자의 파일을 재귀적으로 탐색

확장자 비교는 대소문자를 구분하지 않는다. macOS의 NFD 파일명은 화면 표시와 충돌 판정 시 NFC로 정규화하되, 원본 파일명은 변경하지 않는다.

### 5.2 제외 입력

- `__MACOSX/`, `.DS_Store`, `._*`, 숨김 파일과 숨김 디렉토리
- 심볼릭 링크
- 암호화 ZIP
- 경로에 절대경로 또는 `..`가 포함된 ZIP 항목
- 지원 확장자가 아닌 파일
- 이미 생성된 `*_cuts` 디렉토리

### 5.3 안전 한도

- 한 작업의 입력 파일: 최대 5,000개
- PDF: 파일당 최대 2,000페이지
- ZIP 압축 해제 합계: 최대 4GiB
- ZIP 단일 항목: 최대 500MiB
- ZIP 항목 수: 최대 10,000개
- ZIP 압축비: 항목별 최대 200:1

한도를 초과하면 쓰기 작업을 시작하지 않고 원인을 표시한다.

## 6. 출력 디렉토리와 파일명

### 6.1 단일 이미지

`진실의 방_001_006.jpg`를 선택하면 입력에서 파생된 작업 위치에 다음을 만든다.

```text
진실의 방_001_006_cuts/
├── 진실의 방_001_006/
│   ├── 진실의 방_001_006-01.png
│   ├── 진실의 방_001_006-02.png
│   └── ...
├── summary.csv
├── manifest.json
└── _debug/
    ├── overlay.png
    └── contact-sheet.png
```

- 컷 번호는 위에서 아래 순서로 2자리(`01`, `02`, ...)를 사용한다.
- 모든 컷과 디버그 이미지는 MIME `image/png`의 PNG로 기록한다.
- 원본 crop의 픽셀 크기와 종횡비를 유지하며 확대·축소, 패딩, I2V 모델별 해상도 정규화는 수행하지 않는다.
- alpha가 있는 입력은 alpha를 유지하고, alpha가 없는 입력은 RGB 내용이 변하지 않도록 PNG로 변환한다.

### 6.2 PDF

`과학사_1권.pdf`를 선택하면 다음을 만든다.

```text
과학사_1권_cuts/
├── 과학사_1권/
│   ├── 001-01.png
│   ├── 002-01.png
│   ├── 002-02.png
│   └── ...
├── summary.csv
├── manifest.json
└── _debug/
    ├── 001.png
    ├── 002.png
    └── ...
```

- 페이지 번호는 PDF 페이지 인덱스 기준 1부터 시작하는 3자리 번호다.
- 컷 번호는 페이지별 2자리 번호다.
- PDF 페이지는 `scale = 300 / 72`로 렌더링하며 출력 컷은 PNG다.
- 검출 컷이 없으면 재단선·색상바를 제외한 본문 영역을 `<PDF 파일명>/PPP-01.png`로 저장한다.

### 6.3 입력 디렉토리

작업 위치 안의 `episode-001/`을 선택하면 상대경로를 보존하고 원본 파일마다 독립된 결과 디렉토리를 둔다.

```text
episode-001_cuts/
├── scene-a/
│   └── page-001/
│       ├── page-001-01.png
│       ├── summary.csv
│       └── _debug/overlay.png
├── scene-b/
│   └── page-002/
│       └── ...
└── manifest.json
```

### 6.4 ZIP

`episode-pack.zip` 안에 `scene-a/page-001.jpg`, `scene-b/page-002.pdf`가 있으면 다음을 만든다.

```text
episode-pack_cuts/
├── scene-a/
│   └── page-001/
│       ├── page-001-01.png
│       ├── summary.csv
│       └── _debug/overlay.png
├── scene-b/
│   └── page-002/
│       ├── 001-01.png
│       ├── summary.csv
│       └── _debug/001.png
└── manifest.json
```

규칙은 `<압축파일명>_cuts/<ZIP 내부 원본 상대 디렉토리>/<원본 파일명>/`이다. ZIP 루트의 파일은 `<압축파일명>_cuts/<원본 파일명>/`에 저장한다. ZIP을 로컬에 별도로 풀지 않고 Worker가 항목 단위로 읽어 처리한다.

### 6.5 이름 충돌

- 같은 상대경로에 `page.jpg`와 `page.png`가 함께 있으면 결과 디렉토리를 `page__jpg`, `page__png`로 구분한다.
- 금지 문자는 `_`로 바꾸고, 끝의 공백·마침표를 제거한다.
- 정규화 후 이름이 같으면 입력 목록의 정렬 순서대로 `__2`, `__3`을 붙인다.
- 기존 출력과 manifest의 입력 fingerprint·엔진 버전·옵션이 같으면 재개한다.
- 조건이 다르면 기존 결과를 덮어쓰지 않고 `<입력 이름>_cuts_2`를 제안한다.

## 7. 컷 분할 정책

### 7.1 공통 원칙

- 픽셀을 확대·축소하지 않는다. 분석용 축소본과 출력 원본 좌표를 분리한다.
- 컷 좌표는 `[x0, y0, x1, y1)` 반개구간으로 기록한다.
- 읽기 순서는 기본적으로 위→아래, 같은 행에서는 왼쪽→오른쪽이다.
- 모든 후보에는 `mode`, `confidence`, `flag`를 부여한다.
- 신뢰도가 낮을 때 임의로 세분화하지 않고 더 큰 컷으로 보존한 뒤 검수 플래그를 남긴다.

### 7.2 페이지형/격자형

`/Users/changkyuneun/webtoon Pannel/files/grid_split.py`에서 검증한 정책을 브라우저 Worker용 TypeScript 픽셀 연산으로 이식한다.

1. 기본 본문 영역은 페이지 바깥 3%를 제외해 재단선·색상바를 제거한다.
2. 저채도·저명도 픽셀에서 길게 이어진 가로/세로 테두리 후보를 찾는다.
3. 가까운 선분을 묶어 합집합 coverage를 계산한다.
4. 검은 잉크 점수, 인접 흰 gutter, 페이지별 추정 테두리 두께를 검증한다.
5. 가장 신뢰도 높은 구분선으로 영역을 재귀 분할한다. 최대 깊이는 8이다.
6. 전체 본문 면적의 2% 미만, 너비·높이의 5% 미만, 내용 비율 3% 미만인 조각은 제거한다.
7. 검출 결과가 0개면 본문 전체를 한 컷으로 저장하고 `fullpage` 플래그만 기록한다. `fullpage`는 정상 출력으로 보며 검수 목록에 올리지 않는다.
8. 9컷 이상이면 `many`, 한 변이 페이지 대응 변의 8% 미만이거나 종횡비가 4를 초과하면 `thin`을 기록한다.

### 7.3 세로 웹툰 1차 분리: 공백

검증 기준:

- 전경 픽셀: `min(R,G,B) < 245` 또는 `max(R,G,B)-min(R,G,B) > 8`
- 전경 행: 전경 픽셀 비율 `>= 0.003`
- 분리 공백의 최소 높이: `max(100px, imageWidth × 0.06)`
- 검출 영역에 상하 15px padding을 더하되 이미지 범위를 넘지 않는다.
- 출력은 원본 전체 폭을 유지한다.
- 높이가 폭의 15% 미만이면 `end_card` 후보로 표시한다.
- 높이가 폭의 3배를 초과하면 `continuous_sequence`로 표시한다. 이 조건은 검출 실행 조건이 아니라 긴 장면에 검수 플래그를 붙이는 조건이다.

### 7.4 세로 웹툰 검수 보조: 전체 폭 장면 전환 후보

공백 없이 이어진 긴 컷은 기본 처리 단계에서 임의로 자동 분할하지 않는다. 기본 처리에서는 높이가 폭의 3배를 초과하는 `continuous_sequence` 결과만 `review_continuous` 검수 대상으로 표시한다. 사용자가 검수 화면에서 해당 파일 또는 PDF 페이지를 선택하고 재처리 유형 `수평 장면 전환`을 고른 뒤 실행할 때만 행 경계의 명암·색상 전환 후보를 적용해 재분할한다.

1. 분석용으로 폭 300px까지 축소하고 약한 Gaussian blur를 적용한다.
2. 인접 행의 픽셀 차이 중앙값 `medianJump`를 구한다.
3. 차이가 12 이상인 픽셀의 가로 coverage를 구한다.
4. 경계 위·아래 8행 평균의 명도 차이 `localContrast`를 구한다.
5. 다음 점수로 전환 후보를 정렬한다.

```text
transitionScore = medianJump × (0.25 + coverage12) + 0.35 × localContrast
```

6. 전체 폭의 95% 이상에서 명암·색상이 급변하는 선만 채택한다. 세부 기준은 `coverage12 >= 0.95`, `medianJump >= 40`, `localContrast >= 80`이다.
7. 후보 간 최소 거리는 `max(100px, imageWidth × 0.15)`다.
8. 분리 후 어느 조각도 높이가 `imageWidth × 0.30`보다 작아지면 후보를 기각한다.
9. 액자·창틀처럼 전체 폭을 덮지 않는 내부 선은 coverage 조건으로 제외한다.
10. 최소 컷 높이와 후보 간 최소 거리를 모두 적용해 장식선, 액자선, 너무 촘촘한 선을 제거한다.
11. 기본 처리 결과는 원본 영역을 유지한다. 적합한 후보가 있으면 `review_continuous`, `review_required`와 후보 좌표를 manifest에 기록한다.
12. 사용자가 `선택 유형으로 재처리`를 실행하면 해당 작업 단위만 다시 처리하고 후보 경계를 적용한 새 컷 PNG, summary 행, overlay를 갱신한다. 원본 파일은 수정하지 않는다.

검증한 `진실의 방_001_006-07.jpg`의 기준 결과는 다음과 같다.

| 후보 | 범위 | 높이 | 경계 coverage |
|---|---:|---:|---:|
| 1 | `0:2843` | 2843px | 98.7% |
| 2 | `2843:3754` | 911px | 100% |
| 3 | `3754:8521` | 4767px | - |

`y≈329`의 내부 액자선은 coverage 84%이므로 후보로 사용하지 않는다. 이 파일은 기본 처리에서는 `review_continuous` 후보로 표시하고, 검수 화면에서 재처리 유형 `수평 장면 전환`을 적용하면 3분할되어야 하는 회귀 테스트 정본이다.

### 7.5 입력 유형 자동 감지

- PDF: 페이지형/격자형 정책
- 래스터 이미지의 `height / width >= 2.5`: 세로 웹툰 정책
- 그 외 래스터 이미지: 페이지형/격자형 정책
- 래스터 결과가 `continuous_sequence`로 표시된 긴 영역이면 수평 장면 전환 후보를 계산해 검수 화면에 표시한다.
- 일반 사용자 화면에서는 방식을 직접 선택하지 않는다. 운영 중 필요한 예외는 manifest에 기록되는 내부 옵션으로만 관리한다.

## 8. 출력 메타데이터와 검수 자료

### 8.1 `summary.csv`

UTF-8 BOM CSV로 기록한다.

```text
unit_id,source_path,page,cut,filename,mode,x0,y0,x1,y1,width,height,confidence,flag,elapsed_ms,status,error
```

- `unit_id`는 입력 종류·정규화한 상대경로·PDF 페이지 번호로 만든 결정적 식별자다. 래스터 이미지 하나는 작업 단위 하나이고 PDF는 각 페이지가 작업 단위 하나다.
- `source_path`는 작업 위치 또는 ZIP 루트 기준 상대경로만 기록한다.
- 로컬 절대경로는 기록하지 않는다.
- 성공한 작업 단위에는 컷별 행이 최소 1개 있어야 한다.
- `review_continuous`, `thin`, `many` 중 하나라도 있으면 같은 행에 `review_required`를 함께 기록해 파일·PDF 페이지별 검수 목록을 만들 수 있게 한다. `fullpage`는 정상 출력 플래그이며 단독으로는 `review_required`를 기록하지 않는다.
- 실패한 항목도 `status=error`와 사용자용 오류 문구를 기록한다.
- PDF가 아닌 입력의 `page`는 비운다.

### 8.2 `manifest.json`

최상위 출력 디렉토리에 다음을 기록한다.

- schema version
- 컷 엔진 version
- 입력 종류와 상대경로
- 파일별 `name`, `size`, `lastModified` fingerprint
- 처리 시작 전에 확정한 `expectedUnitCount`와 정렬된 작업 단위 목록
- 작업 단위별 `unitId`, 원본 상대경로, PDF 페이지, `pending|running|completed|error` 상태, 시도 횟수, 생성 컷 경로·크기
- 선택 옵션과 임계값
- 완료된 파일·PDF 페이지
- 생성 파일 상대경로
- 작업 시작·수정·완료 시각
- 총계와 플래그별 건수

manifest는 매 파일 또는 PDF 페이지가 원자적으로 완료된 뒤 갱신한다. 임시 파일은 `<name>.partial`로 기록한 뒤 같은 디렉토리에서 최종 이름으로 교체한다. `completed` 작업 단위는 컷 수가 1개 이상이고 모든 기록된 컷 파일의 PNG signature·디코딩 가능 여부·픽셀 크기 검증이 끝난 뒤에만 기록한다.

### 8.3 `_debug/`

- 단일 이미지: `overlay.png`, `contact-sheet.png`
- PDF: 페이지별 `PPP.png`
- 오버레이는 분석 좌표가 원본 좌표와 일치하도록 그린 축소본이다.
- 각 박스에 컷 번호, mode, confidence, flag를 표시한다.
- 디버그 자료 생성 실패는 컷 파일 생성을 실패로 바꾸지 않으며 `debug_error` 플래그를 남긴다.

## 9. 실행·재개·취소

- `WebtoonCutJobProvider`를 `StudioShell`보다 상위에 두어 라우트가 바뀌어도 활성 작업 객체가 unmount되지 않게 한다.
- Provider는 인증 사용자와 브라우저 탭별로 활성 작업 1개의 디렉토리 handle, 선택 입력, 옵션, 진행률, 플래그, manifest 상태, Worker와 controller를 소유한다.
- 컷 분할 화면은 Provider 상태를 구독할 뿐이며, 화면 unmount나 다른 DOBEDUB 메뉴로 이동하는 동작은 Worker를 종료하거나 handle을 해제하지 않는다.
- 컷 분할 화면에 재진입하면 실행 중·중지·완료·실패 상태와 누적 진행률을 같은 Provider에서 즉시 복원한다.
- 다른 새 컷 분할 작업은 현재 작업이 완료되거나 안전하게 중지된 뒤 시작할 수 있다.
- 처리 시작 전에 이미지 파일은 파일별 1개, PDF는 페이지별 1개의 정렬된 작업 단위 inventory를 만들고 manifest에 먼저 기록한다. 디렉토리와 ZIP도 내부 입력 전체를 같은 방식으로 펼쳐 총 작업 단위를 확정한다.
- PDF 페이지 수나 ZIP 항목 목록을 끝까지 확정할 수 없으면 불완전한 inventory로 실행하지 않고 쓰기 전에 `inventory_error`로 실패한다.
- Worker는 래스터 입력 1개 또는 PDF 페이지 1개씩 처리하고 `ImageBitmap`, canvas, typed array를 즉시 해제한다.
- ZIP 전체를 한 번에 메모리에 풀지 않고 항목 단위로 처리한다.
- 실행 중 UI thread를 막지 않는다.
- 사용자가 중지하면 현재 원자 단위를 마친 뒤 중지하고 manifest에 `paused`를 기록한다.
- 재개 시 fingerprint, 엔진 version, 옵션이 같더라도 기록된 출력 PNG가 없거나 signature·디코딩·픽셀 크기 검증에 실패한 단위는 완료로 보지 않고 다시 처리한다.
- 하나의 입력이 실패해도 디렉토리·ZIP의 나머지 입력은 계속 처리한다.
- 종료 직전에 inventory, manifest, `summary.csv`, 실제 출력 파일을 대조한다. 모든 작업 단위가 정확히 한 terminal 상태이고, 성공 단위마다 컷이 1개 이상 존재해야 한다.
- 누락되거나 손상된 출력은 해당 작업 단위만 자동으로 1회 다시 처리한다. 그래도 복구되지 않으면 `missing_output` 오류로 남기고 작업 상태를 `completed_with_errors`로 표시하며, 정상 완료로 표시하지 않는다.
- 모든 출력이 존재해도 `review_required` 단위가 하나 이상이면 `completed_with_review`로 표시한다. 이는 처리 누락이 아니라 분할 결과에 사람 확인이 필요하다는 상태다.
- 로그아웃이나 인증 사용자 변경 시 Provider는 현재 원자 단위가 끝난 뒤 작업을 안전 중지하고 Worker와 handle 참조를 해제해 사용자 간 상태가 섞이지 않게 한다.
- 브라우저 탭을 닫으면 백그라운드 처리를 보장하지 않는다. 다시 열어 같은 입력 또는 출력 위치 권한을 다시 부여하면 manifest에서 재개한다.

## 10. 개인정보·보안 요구사항

- 컷 분할 코드에서 `fetch`, `XMLHttpRequest`, `WebSocket`, `sendBeacon`으로 `File`, `Blob`, `ArrayBuffer`, `ImageBitmap`, 파일명 또는 상대경로를 전송하지 않는다.
- ECS·FastAPI API에는 컷 분할 입력/출력 엔드포인트를 추가하지 않는다.
- 파일 선택과 쓰기 권한은 반드시 사용자 제스처 뒤에 요청한다.
- 선택한 입력과 파생된 작업·출력 위치 밖의 경로를 탐색하거나 기록하지 않는다.
- ZIP 경로는 POSIX 상대경로로 정규화한 뒤 절대경로, `..`, 심볼릭 링크를 거부한다.
- 로그에는 파일명 대신 항목 수, 처리 시간, 오류 코드만 표시한다. 원격 관측성 전송은 기본 비활성화한다.
- 브라우저가 권한을 잃으면 작업을 중지하고 재선택을 요청한다.

## 11. 성능 기준

- 기준 장치: Apple Silicon Mac, 데스크톱 Chrome

- 진행률은 500ms보다 자주 렌더링하지 않는다.
- 분석은 필요 시 축소본을 사용하되 출력 crop 좌표는 원본 픽셀 좌표로 환산한다.

## 12. 오류 처리

| 상황 | 동작 |
|---|---|
| 지원하지 않는 브라우저 | 입력 선택과 쓰기 작업을 막고 Chrome/Edge 안내 |
| 읽기 또는 쓰기 권한 거부 | 파일을 만들지 않고 재요청 안내 |
| 손상 래스터 또는 개별 PDF 페이지 렌더 실패 | 해당 작업 단위를 `error`로 기록하고 다음 단위 계속 |
| PDF 페이지 수 또는 ZIP 항목 inventory 확정 실패 | 출력 쓰기 전에 작업을 `inventory_error`로 종료 |
| ZIP 보안 규칙 위반 | ZIP 전체를 처리하지 않고 출력 쓰기 시작 전 종료 |
| 저장 공간 부족 | 현재 `.partial` 정리 후 중지, 완료 파일 유지 |
| 기존 출력과 조건 불일치 | 덮어쓰지 않고 새 출력 폴더 제안 |
| 컷 0개 | 본문 전체를 1컷으로 저장, `fullpage` 표시 |
| 긴 연속 컷의 경계 신뢰도 부족 | 하나로 유지, `review_continuous` 표시 |
| 분할 품질상 누락 가능성 | `review_required`로 원본 파일/PDF 페이지와 오버레이를 검수 목록에 표시 |
| inventory에는 있으나 manifest/CSV 행이 없는 단위 | 해당 단위만 자동 재처리 후 `missing_output` 또는 완료 기록 |
| 완료 기록의 PNG가 없거나 손상됨 | 완료를 취소하고 해당 단위만 재처리; 실패 시 `completed_with_errors` |

## 13. 수용 기준

### 13.1 기능

- `jobs:run` 사용자가 `GENERATE` 위의 독립 `LOCAL` 메뉴에서 `이미지 컷 분할` 화면에 진입할 수 있다.
- 권한이 없는 사용자는 메뉴를 볼 수 없고 직접 URL 진입 시 기존 403 화면을 본다.
- 입력 파일·폴더·ZIP을 선택하지 않으면 inventory와 실행을 시작할 수 없다.
- 단일 이미지, PDF, 디렉토리, ZIP에서 §6의 출력 구조가 정확히 생성된다.
- 입력 확장자와 관계없이 생성되는 컷과 `_debug/` 이미지의 확장자는 `.png`, MIME은 `image/png`다.
- 모든 컷의 실제 크기와 `summary.csv`의 좌표·크기가 일치한다.
- PDF의 선언 페이지 수와 inventory의 페이지 단위 수가 같고, `1..pageCount`가 중복·공백 없이 존재한다.
- 여러 이미지 입력에서는 탐색된 지원 이미지 수와 inventory의 이미지 단위 수가 같고, 각 상대경로가 정확히 한 번 존재한다.
- 작업이 `completed`이면 `expectedUnitCount = completedUnitCount`, `pending|running|error` 단위가 0개이며 모든 성공 단위에 검증된 PNG 컷이 1개 이상 있다.
- 오류나 복구 불가능한 누락이 하나라도 있으면 `completed`가 아니라 `completed_with_errors`로 표시하고 해당 단위 목록과 재시도 기능을 제공한다.
- 출력 무결성 오류는 없지만 `review_required`가 하나라도 있으면 `completed_with_review`로 표시하고 원본 이미지 또는 PDF 페이지별 검수 목록을 제공한다.
- 같은 조건으로 재실행하면 완료된 파일·페이지를 건너뛴다.
- 실행 중 다른 DOBEDUB 라우트로 이동해도 Worker와 디렉토리 handle이 유지되고, 화면 재진입 시 같은 작업의 상태와 진행률이 표시된다.
- 로그아웃 시 활성 작업은 안전 중지되고 이전 사용자의 로컬 handle과 작업 상태가 다음 사용자에게 노출되지 않는다.
- 원본 파일은 수정·이동·삭제되지 않는다.

### 13.2 분리 정확도 회귀 표본

- `진실의 방_001_009.jpg`: 본편 4컷 + `end_card` 1컷
- `진실의 방_001_006.jpg`: 기본 처리에서 최종 연속 연출을 `review_continuous` 후보로 표시하고, `수평 장면 전환` 재처리 후 기대 컷 수로 분리
- `진실의 방_001_006-07.jpg`: 기본 처리에서 `review_continuous` 후보로 표시하고, `수평 장면 전환` 재처리 후 `[0:2843]`, `[2843:3754]`, `[3754:8521]` 3컷
- 흰 공백이 없고 `height > width × 3`인 합성 이미지: 전체 폭 coverage 95% 이상의 강한 수평 전환을 `review_continuous` 후보로 기록하고, 선택 유형으로 재처리 후 2컷 이상으로 분리
- `과학사 1.png`: 기존 `grid_split.py`와 같은 읽기 순서·컷 수
- PDF 컷 0개 페이지: 본문 전체 1컷과 `fullpage` 플래그
- 완료 manifest의 컷 파일 하나를 제거한 재개 테스트: 해당 단위만 다시 처리하고 정상 단위는 건너뜀

### 13.3 네트워크 격리

- 브라우저 Network 기록에서 컷 실행 중 이미지·PDF·ZIP 업로드 요청이 0건이다.
- 결과 생성에 HTTP 다운로드 응답을 사용하지 않는다.
- ECS 로그, EFS, S3, RDS 어디에도 선택 파일과 결과 컷이 생기지 않는다.

### 13.4 제공 경로 동등성

- 같은 브라우저·같은 입력·같은 엔진 version·같은 정책에서 로컬 개발판과 ECS 배포판의 좌표, 컷 수, 플래그가 동일하다.
- 출력 PNG의 비필수 metadata 또는 압축 바이트 차이는 허용하지만 디코딩한 픽셀 크기와 crop 영역은 같아야 한다.
